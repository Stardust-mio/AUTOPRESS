## 1. Goals and non-goals

AutoPress is a general-purpose Windows 10/11 desktop tool (PyQt6, modern UI) that enters game redeem / gift /
serial codes for the user, one after another, into ANY game client or web redemption page. Users are non-technical;
zh-TW is the primary language, English secondary. Personas (ux.md 5.1): casual multi-game player (3-10 codes per
livestream, often screenshots), key collector (20-50 keys, CSV, history), profile author (shares profiles).

### 1.2 Non-goals (deferred or never)
Deferred: click-image step (template matching), loops / branches / conditional steps (MVP: click_text
`on_not_found` = continue covers "dismiss the popup if there is one"), several profiles in one run,
drag-reordering the queue (buttons in MVP), scheduled runs, opt-in code feeds, online template gallery, auto-update,
Steam template, Korean OCR and Korean result keywords (needs a second 13.5 MB recogniser), Windows Graphics
Capture / PrintWindow for occluded or exclusive-fullscreen windows, a two-point 校正 (re-calibration) wizard (MVP:
「重新對準」 re-picks every position with the setup wizard; DPI-scaled offsets; preview), per-point alignment chosen
by templates and click offsets in text-height units, a compact attention card on the mini bar (MVP: the main
window comes back), per-item OCR source crops kept after import, case-sensitive typed-text verification,
language-independent message keys for persisted texts, a full English user guide (README English quick start
only), live language switching after the first run (restart instead), multi-account. The ux.md "if_stop" step is
not a step type: the same behaviour (stop / cool down on rate limits, stop after N failures, pause after N invalid
results, unknown results) lives in the profile's `RunPolicy`.
Never: code generation, guessing, brute force or O/0-variant retries; shipped code lists; telemetry or any network
use at runtime; low-level keyboard/mouse hooks; anti-cheat bypass; ticking consent boxes for the user.

## 2. Architecture and threads

```
GUI thread (Qt event loop)                     runner QThread (one at a time)      OCR worker (daemon thread)
  MainWindow, pages, overlays, MiniBar           Runner (G4)                         OcrService worker (G2)
  AppContext: Settings, ProfileStore (A1),       - RunControl checkpoints/sleep      - owns OcrEngine (RapidOCR)
    CodeQueue + HistoryStore (G1)                - RealBackend: win32 input (G3),    - priority queue (runner 0,
  RunSession (G4, facade) <==queued signals==      capture.Grabber (G2) + masking,     UI imports 1)
  GlobalHotkeys (G3) -> RunFlow (pause/resume/stop)  OCR calls, keep_awake
  RunFlow -> session.set_masked_rects(mini bar)  -- ocr.recognize() blocking -->
  ocr.request(...) callbacks on GUI thread <------------------------------------------- results
```

### 2.1 Thread rules
* GUI thread: all widgets and overlays; ALL stores (CodeQueue, HistoryStore, ProfileStore, settings) - single
  writer; RunSession; GlobalHotkeys; toasts. It never blocks longer than about 50 ms: no OCR, no sleeps, no waiting
  on futures, no input injection.
* Runner thread: created by RunSession per run or step test. It never touches widgets or stores. Output only via
  Runner signals (queued to RunSession) and return values; input only via RunControl and the plan (deep copies).
* OCR worker: one per app, a daemon `threading.Thread` (never a QThread), owns the engine; the GUI uses
  `OcrService.request()` (callbacks on the GUI thread), the runner uses `OcrService.recognize()` (blocking,
  cancellable, priority 0). The `OcrService` object is never replaced (RunSession keeps it): new OCR settings and
  「重新啟動引擎」 call `ctx.ocr.restart(settings.ocr)`.
* Capture: one `capture.Grabber` per thread; create it only after QApplication exists (mss before QApplication locks
  the process into PMv1 DPI awareness - measured). Physical pixels everywhere except Qt's own drawing. Every
  runner capture has AutoPress's own visible windows blanked (`RunSession.set_masked_rects` +
  `ocr.imageio.mask_rects`) before OCR, blank checks and evidence: mss copies screen pixels, so the topmost mini bar
  would otherwise be read (its 「已使用 1」 chip is a USED keyword).

### 2.2 UI <-> runner
RunSession re-emits on the GUI thread, after updating queue and history: `state_changed(state, reason)`,
`progress(done, total, eta_s)`, `code_started(code_id, index)`, `step_started(code_id, step_index, title)`,
`code_finished(code_id, AttemptRecord)`, `log(LogEntry)`, `cooldown(seconds_left)` (rate-limit cool-down),
`waiting(seconds_left)` (interval before the next code), `attention(Attention)`,
`finished(RunSummary)`, `test_finished(StepTestResult)`. UI requests are plain method calls
(`pause/resume/toggle_pause/stop/resolve_attention/update_keywords/set_masked_rects`) that set RunControl flags or
lock-protected values (thread-safe); the UI never touches the Runner object. RunSession bookkeeping: `code_started`
-> item RUNNING, attempts+1; `code_finished` -> item status/message, `history.append(record)` unless the attempt was
interrupted before submit; a `code_finished` for an id no longer in the queue is logged and ignored; on `finished`
any plan item still RUNNING becomes REVIEW (「執行中斷，請確認是否已兌換」 / "The run was interrupted; check whether
this code was redeemed"); `resolve_attention` changes the queue item and, through `HistoryStore.update`, the
attempt's history record in place.

### 2.3 Blocking waits
Every wait in the runner (step delays, key delays inside `win32.input` via the `sleep=` argument, polling loops of
click_text / wait_text / ocr_check, interval between codes, cool-down, pause) goes through `RunControl.sleep()`:
slices of at most 50 ms, each slice calls `checkpoint()` (stop -> StopRequested) and `tick()` (failsafe corner ->
FailsafeTriggered). Physical input is checked ONLY by `InjectGuard.check()` right before every injection (integration,
gate G-07): input during a wait trips at the next keystroke / click, before anything is sent, so a result read after
submitting is never aborted and F8 during a wait is the soft pause of 2.6. OCR inference (0.2-1.5 s for regions and full-HD
clients, up to 4.5 s for a live 4K desktop; ocr.md 3.4) is the only non-interruptible wait; the runner checks right
after it. `wait_while_paused()` blocks on a condition variable and runs no input checks (a paused run never trips).

### 2.4 Run lifecycle ("開始兌換", RunFlow G7 + RunSession G4)
1. Run page or Codes page -> `RunFlow.begin(profile, selection)` (the RunFlow is created lazily on first use; each
   page may own one, but only ONE is active: `begin` registers it in `ctx.extras["g7.active_run_flow"]` and refuses
   while another flow or the session is active, and `resume` / `stop` / the Run page's buttons always act on the
   active flow - integration, gate G-05);
   `plan = session.build_plan(...)` (only codes of `profile.game_key()`; history-done codes -> SKIPPED, daily cap
   applied); `report = session.preflight(plan)`.
2. Preflight sheet (parented to the main window): errors block (with action buttons), warnings need a click, info is
   shown (incl. the `estimate` line). More than `confirm_run_over` codes -> confirm.
3. Register hotkeys (`pause_resume` -> RunFlow's pause / resume handling, `stop` -> cancel the countdown, later
   `session.stop`). A failure (1409) opens a warning DIALOG (7.1 text; 繼續 / 取消) - toasts are dropped in run mode -
   and forces the MiniBar on for this run.
4. `CountdownOverlay.start(countdown_s, monitor_rect, hint)` on the target's monitor; the hint shows F9 and an arrow
   to the failsafe corner (`models.failsafe_corners`); F9 cancels.
5. `main_window.set_run_mode(True)` (hidden; minimised instead when `minibar_enabled` is False and the hotkeys
   registered, so the taskbar button stays); the MiniBar appears, placed with
   `place_away_from(preview_profile rects, target client rect)`, `win32.windows.exclude_from_capture` applied, and its
   physical frame published with `session.set_masked_rects` (again after every move; `[]` when hidden);
   `session.start(plan)`.
6. Runner thread: `win32.power.keep_awake(True)`, reset the input baseline, then the per-code loop (2.5); in its
   `finally` `keep_awake(False)`. Foreground is granted because the run starts from the user's click and the
   foreground routine uses the zero-move / AttachThreadInput tricks (win32_input.md 5).
7. Pauses: an `attention` whose reason `PauseReason.opens_main_window` (unknown or ambiguous result, invalid streak,
   error, title / size change, blank capture, target lost) restores the main window on the Run page - the run is
   already paused, so taking the focus is harmless; USER / USER_INPUT / FOCUS_LOST / POINT_BLOCKED pauses stay on the
   MiniBar (reason text + 繼續 / 停止 / 展開). 展開 while running requests a soft pause and restores the main window
   once PAUSED. `RunFlow.resume()` (button or F8) hides the main window again, shows the resume countdown
   (`resume_countdown_s`, F9 = stop) and then calls `session.resume()`.
8. `finished` -> unregister hotkeys, hide MiniBar, `set_masked_rects([])`, `set_run_mode(False)`, summary toast,
   navigate to the Run page (summary card). A TEST_ONE run whose code reached a final status other than FAILED /
   REVIEW sets `profile.last_test_ok_at` and saves the profile.

### 2.5 Per-code algorithm (Runner, G4)
```
submit_index = profile.first_submit_index(); start_size = client size of the target when the run starts
for item in plan.items (queue order):
    honour soft pause (state PAUSED until resume); checkpoint()
    target alive (WindowInfo pid/exe/class)? else re-find with profile.target, using only RESOLVED windows whose
        program is not in FORBIDDEN_TARGET_EXES and not AutoPress; none -> pause TARGET_LOST; once the run had a
        window, a DIFFERENT matching window is used only after the user confirmed it (TARGET_LOST pause naming the
        candidate; several candidates -> pause until one is left) - gate G-03
    alive but profile.target.matches(exe, CURRENT title, class) is False (tab changed) -> pause TITLE_CHANGED
    bring_to_foreground(target) (restores a minimized window, then waits until two client_rect reads 100 ms apart
        agree, max 5 s - exclusive-fullscreen games switch display mode) else pause FOCUS_LOST
        (message 「無法把目標視窗切到最前面」); sleep(after-focus settle)
    client size != start_size -> pause SIZE_CHANGED (resume accepts the new size as start_size)
    emit code_started; possibly_submitted = False; result = None
    for each enabled step (StepType.UNKNOWN skipped): emit step_started
        before the step at submit_index: if an enabled ocr_check has only_new_text, capture + OCR its region once
            (the baseline lines)
        before every step that sends input: the CURRENT title must still match (a browser keeps its HWND when the
            tab changes) else pause TITLE_CHANGED (item as for guard trips) - gate G-04
        execute (5.3); a step at index >= submit_index that sent input sets possibly_submitted
        every capture: masked rects blanked; a capture that looks blank is re-checked on the WHOLE client area and
            only a blank client pauses CAPTURE_BLANK (item as for guard trips); a uniform region (empty result area,
            the baseline read, wait_text "disappear") never pauses by itself - gate G-01
    status = models.status_for_result(result)
  except UserActivity | ForegroundLost | PointNotOnTarget | InputBlocked: hard pause with that reason (InputBlocked
        -> ERROR with its text; Attention + state PAUSED); item -> PENDING (retried after resume) or, if
        possibly_submitted, REVIEW 「中斷於送出後，請確認是否已兌換」 / "Interrupted after submitting; check whether it
        was redeemed"
  except FailsafeTriggered: stop(FAILSAFE)        except StopRequested: item handled as above, run ends
  except StepError: result already set by ocr_check -> keep it, log the error as a warning; else
        possibly_submitted -> REVIEW 「送出後的步驟失敗，請確認是否已兌換：{reason}」; else FAILED with the message
  except OSError while the target no longer exists (client_rect / capture of a closed window) -> pause TARGET_LOST,
        item PENDING / REVIEW as for guard trips
  except Exception (anything else): log the traceback; item REVIEW if possibly_submitted else PENDING; pause ERROR
        (Attention with 7.1 "unexpected error" text; the Run page offers 開啟紀錄檔)
  (order, gate G-11: rate limit, then the unknown-result decision, then the counters)
  RATE_LIMITED: policy.on_rate_limit == cooldown and cooldowns_used < max_cooldowns (per run) -> state COOLDOWN, emit
        cooldown every second for cooldown_s (paused time does not count), retry the SAME code; else
        stop(RATE_LIMITED), item -> PENDING with message; COOLDOWN neither counts nor resets the counters
  UNKNOWN (status REVIEW): on_unknown pause -> Attention(UNKNOWN_RESULT, ocr_text, evidence) + pause; continue;
        stop -> StopReason.ERROR with the unknown-result text
  counters use the status the user chose in that attention (`resolve_attention`), else the attempt's status:
  consecutive failures (FAILED, REVIEW) >= policy.stop_after_failures (> 0) -> stop(FAILURES)
  consecutive INVALID >= policy.pause_after_invalid (> 0) -> pause INVALID_STREAK (Attention, 7.1 text; resume resets)
        any other final status resets both counters
  wait uniform(interval_min_s, interval_max_s), emitting waiting(seconds_left) about once per second, unless it was
        the last code; after a resume wait at least
        interval_min_s since the last submit
  (the per-code `try` covers code_started .. final status only: the cool-down and the interval run after the item
   is final, so a stop or failsafe there never changes it; an item still COOLDOWN at run end becomes PENDING with
   its message kept - gate G-06)
finally: release everything we hold (modifiers, keys, mouse buttons); keep_awake(False); emit finished(RunSummary)
```

### 2.6 Pause, resume, stop, abort
| Trigger | Effect | Current code |
|---|---|---|
| `pause()` - button or F8 while running | soft: after the current code; at once when waiting between codes. Idempotent (no-op while pausing / paused) | finishes normally |
| guard trip: focus lost, click point covered, physical input (`pause_on_user_input`), input blocked | hard pause before the next keystroke / click | PENDING, or REVIEW if possibly submitted |
| F8 within 1.5 s after an automatic pause | counts as pause: a USER_INPUT pause is relabelled USER (the key press itself tripped the guard), never resumes | - |
| `RunFlow.resume()` - button or F8 while paused | main window hidden again, resume countdown (`resume_countdown_s`, default 2 s, F9 = stop), then `session.resume()`: reset input baseline, re-focus, continue | retried if PENDING |
| 展開 on the MiniBar while running | soft pause; the main window comes back when PAUSED | finishes normally |
| attention (unknown result, invalid streak, error, title / size change, blank capture, target lost) | PAUSED + Attention; the main window comes back on the Run page | per 2.5 |
| `stop()` - button or F9 (F9 during a countdown cancels it) | at the next checkpoint (<= 50 ms in waits, right after an OCR call) | PENDING / REVIEW as above |
| failsafe: cursor within `failsafe_margin_px` of an outer top-left desktop corner (`models.failsafe_corners`; on this PC the LEFT monitor's top-left, not (0, 0)) | abort = stop(FAILSAFE) + release keys and buttons | PENDING / REVIEW |
| app exit during a run | `session.shutdown()`: stop + join (3 s) + deliver the queued final signals | PENDING / REVIEW |
| crash / kill | queue.json still says RUNNING -> `recover_after_crash()` at next start | REVIEW |

With `pause_on_user_input` on, pressing F8 or moving to the MiniBar is itself physical input: during input steps
the guard trips at the next keystroke / click (hard pause, then relabelled USER); during waits (ocr_check polling,
wait steps, the interval) nothing trips, F8 is the soft pause and the result is still read (gate G-07). The MiniBar's pause / resume button is disabled for 0.7 s after every
state change, so a click aimed at 暫停 never lands on a freshly shown 繼續. Interrupted-before-submit attempts are not
written to the history.

### 2.7 Safety invariants (G3 implements, G4 enforces)
1. `InjectGuard.check()` before EVERY character, key combo and click: target is the foreground window (or, with
   `TargetMatch.allow_same_process`, a window of the target process); for clicks the root window under the point is
   the target (with `allow_same_process`: a window of the target process; coordinates still resolve against the
   target's client rect). Never type when the target is not foreground. PointNotOnTarget names the covering
   window (AutoPress's own mini bar gets its own message, 7.1).
2. One atomic SendInput per character/combo; EVERY key and mouse button we press is released in `finally` before an
   exception propagates (also when the hold's sleep raises); clipboard snapshot and IME state are restored in
   `finally`; `release_all_modifiers()` (also releases anything still held by us) at run end, on abort and at app
   exit. SendInput inserting fewer events than sent raises InputBlocked (hard pause).
3. Elevated target (UIPI drops input silently): preflight error with "restart as administrator".
4. Runs start only from an explicit click plus countdown; never at app start; hotkeys only registered during runs and
   real step tests. Step tests are dry runs by default; a real step test gets the countdown, the stop hotkey and a
   停止測試 button.
5. Minimum 1 s between codes (models clamp), default 6-8 s; stop or cool down on rate-limit text.
6. Codes only from the user; never generate, guess, or retry O/0 or I/1 variants (ask the user instead).
7. A shared profile is executable input. Key steps refuse Win combos and system shortcuts (`models.combo_risk`
   ERROR: Alt+Tab, Alt+Esc, Alt+F4, Alt+Space, Ctrl+Esc, Ctrl+Shift+Esc, Ctrl+Alt+Delete), browser developer tools /
   page source (F12, Ctrl+Shift+I/J/C/K, Ctrl+U) and paste (Ctrl+V, Ctrl+Shift+V, Shift+Insert); with a browser
   target (or a browser `suggested_exe`) also the address-bar / search shortcuts (`models.ADDRESS_BAR_COMBOS`); a
   type_text with a line break, tab or script URL is a validation warning and a risky import line
   (`models.text_is_risky`); shells, terminals and system UI (`models.FORBIDDEN_TARGET_EXES`) are never a target,
   checked on the profile's exe AND on every resolved window (preflight, runner re-find); a target without exe needs
   a window class or an exact title (`TargetMatch.exe_unknown`, preflight `target_exe_unknown`); a browser target needs
   a title keyword, and the title is re-checked before every code and before every input step; imports never keep the
   author's target (`Profile.prepare_import`) and are saved only after the user confirmed the literal step list
   (`Profile.action_lines`) and the non-default run rules (`Profile.policy_lines`) - integration, gates G-02 / G-03.
8. Failsafe = the cursor in an OUTER top-left corner of the desktop (`models.in_failsafe_corner`), shown on the
   countdown and in the MiniBar tooltip; F9 is the stop for games that confine the cursor.
9. AutoPress's own windows never reach OCR (masked captures) and never silently swallow a click (guard message).

### 2.8 Startup and shutdown (G5, `autopress/ui/app.py`)
1. `main.py` / `autopress/__main__.py` set `OPENBLAS_NUM_THREADS=1` before anything imports numpy. `ui.app.main`
   dispatches `--selftest report.json` FIRST to `autopress.selftest.run` (G8; it creates or reuses the
   QApplication). Then `logsetup.setup_logging()`; `install_excepthook()` - the UI shows
   「發生未預期的錯誤，已記錄在紀錄檔。」 with an 開啟資料夾 action (never the raw exception text).
2. `QApplication` BEFORE any capture / mss / dpi call -> per-monitor-v2; `app.setQuitOnLastWindowClosed(False)` (in
   run mode only Tool windows remain visible, so closing any dialog would quit mid-run - measured); the app quits
   explicitly from `MainWindow.closeEvent` (confirm + `session.stop()` during a run). Single instance:
   `QLockFile(paths.lock_path())`; with `--wait-lock` (set by `restart_as_admin`) `tryLock(10000)`; if still locked
   show 「AutoPress 已在執行中」 and exit.
3. `storage.load_settings()`; `i18n.set_language(settings.language)`; qtbase_zh_TW translator for zh-TW; `apply_theme`.
   `paths.resolve_data_dir()` reports a fallback -> the startup banner of 7.1.
4. `build_context()`: ProfileStore; CodeQueue.load + recover_after_crash; HistoryStore.load +
   prune_evidence(evidence_keep_days); OcrService(settings.ocr); RunSession(queue, history, ocr); GlobalHotkeys.
5. `show_welcome_if_needed(ctx, None)` BEFORE the main window exists: a language picked there applies at once
   (`set_language` + translator switch), no restart.
6. `MainWindow(ctx)` (sets `ctx.main_window`, attaches hotkeys to its HWND), restore geometry, show.
7. `ocr.start()` when `settings.ocr.enabled` (warm-up in the worker, ~1.1 s to first result).
8. Quit (`aboutToQuit`): session.shutdown (joins and delivers the final bookkeeping), hotkeys.unregister_all,
   input.release_all_modifiers, ocr.shutdown, save settings (window geometry), queue.save.
Every dialog has a parent (main window, or the MiniBar during runs); parent None only before the main window exists.

## 4. Interfaces

### 4.1 Contract
* The stubs define every public module; signatures below are generated from them. Return values and exceptions are
  as documented in the stub docstrings. Geometry: physical pixels, `Rect = (x, y, w, h)`, `Point = (x, y)`.
* Images: numpy uint8, HxWx3 BGR (OCR input) or HxWx4 BGRA (capture). Never give OpenCV a file path.
* Localized messages: exceptions documented as "localized" carry a `tr()` text the UI can show as is.
* Pages and dialogs take the `AppContext` first (`CodesPage(ctx)`); `ctx.main_window` may be None in tests. The
  services in the context (`ctx.ocr`, `ctx.session`, stores, hotkeys) are created once and never replaced.
* What the UI needs, and where: list windows `win32.windows.list_windows`; window under a point
  `win32.windows.window_at` (overlays hide themselves first; `skip_own=True` looks through AutoPress's windows);
  pick point / region / window `ui.overlays.pick`; capture `capture.grab_rect` / `Grabber`; OCR an image
  `ctx.ocr.request`; find text `ocr.textfind.find_text`; extract codes `codes.extract.extract_from_text /
  extract_from_ocr`; run a profile `RunFlow.begin` -> `RunSession.start`; resume `RunFlow.resume`; test one step
  `RunSession.test_step`; preview points `runner.preview.preview_profile` + `ui.overlays.PreviewOverlay` (the same
  rects feed `MiniBar.place_away_from`); keep own windows out of captures `RunSession.set_masked_rects` +
  `win32.windows.exclude_from_capture`; client-relative points `models.record_point / resolve_point(...,
  dpi=win32.windows.window_dpi(hwnd))` with `win32.windows.client_rect`; import a profile
  `ProfileStore.read_file` -> `Profile.action_lines` -> `ProfileStore.import_profile`.

## 5. Data model (exact definitions: `autopress/models.py`)

### 5.1 Files (UTF-8 JSON written atomically by `storage.write_json`; GUI thread only)
| File in the data folder | Content | Writer |
|---|---|---|
| `settings.json` | `Settings` | `AppContext.save_settings()` (G5 settings page, A1 helpers) |
| `profiles/<id>.autopress.json` | one `Profile` each | `ProfileStore` (G7 pages) |
| `queue.json` | `{"schema_version": 1, "items": [CodeItem...]}` | `CodeQueue` (G1) |
| `history.jsonl` | one `AttemptRecord` per line + `"schema_version"` | `HistoryStore` (G1) via RunSession (G4); the Codes page's 標記為已兌換 (G6, run_id "manual") |
| `evidence/<yyyy-mm-dd>/<run_id>_<n>.png` | result-region crops (own windows masked) | runner backend (G4) with `imageio.save_png` |
| `logs/autopress.log` | rotating log, codes masked | `logsetup` |
Data folder: `%AUTOPRESS_HOME%` (tests) > portable (`portable.txt` next to the exe or project root -> `<app>/data`) >
`%APPDATA%/AutoPress` > `%TEMP%/AutoPress` (when the others cannot be written). Resolved ONCE per process
(`paths.resolve_data_dir`, one write probe) and cached, so threads never race on probe files and the folder never
changes mid-session; the intended folder of a fallback feeds the startup banner (7.1). Only files inside the data
folder are renamed `*.broken-<ts>` when broken. Every atomic write uses `storage.write_bytes_atomic` (O_EXCL temp
file; never `tempfile.mkstemp`, which loops for a long time in ACL-denied folders). Release zips do not contain
`portable.txt`; README explains how to create it. Bundled read-only resources: `autopress/resources/`
(`paths.resource_path`, `paths.templates_dir`).

### 5.2 Profile
`Profile` = schema_version, id, name, game (history key `game_key()` = "game:<squashed game>" or "profile:<id>"),
description, author, `target: TargetMatch` (exe basename case-insensitive, title contains/exact/regex/any, class
exact, allow_same_process), `suggested_exe` (import hint only), `coord_mode` (auto/offset/ratio),
`code_format: CodeFormat`, `steps: list[Step]`, `keywords: KeywordConfig`, `policy: RunPolicy` (interval 6-8 s,
rate limit cooldown 300 s x1 then stop, stop after 3 failures, pause after 3 invalid results, unknown -> pause),
`template: TemplateInfo | None` (built-ins only), timestamps, `last_test_ok_at` ("" = never tested successfully).
Positions are `ClientPoint` / `ClientRegion`: physical-pixel offsets from the target's client area AND ratios plus
the reference client size and DPI (win32_windows.md 6, verified math). `auto` resolves by offset when the client
size and DPI equal the recorded ones, else by ratio; `offset` keeps the distance to the point's anchor (左上 /
右上 / 左下 / 右下 / 置中, chosen in the step editor) scaled by `window_dpi / ref_dpi` (web pages and dialogs grow
with Windows scaling; web templates use offset, game templates auto or ratio). Record with
`models.record_point(win32.windows.client_rect(hwnd), x, y, dpi=win32.windows.window_dpi(hwnd))` and resolve with
`dpi=window_dpi(hwnd)`. Shared files never contain codes, history or screenshots; their target keeps exe and class
plus at most a title keyword the author confirmed, never `allow_same_process`, and an import never uses it
(`Profile.prepare_import`).
Example (abbreviated): `{"schema_version": 1, "id": "3f2a9c1d0b7e4a55", "name": "網頁兌換", "game": "原神",
"target": {"exe": "chrome.exe", "title": "兌換", "title_mode": "contains", "class_name": "", "allow_same_process":
false}, "coord_mode": "auto", "code_format": {"id": "hoyoverse", "charset": "A-Za-z0-9", "case_sensitive": true,
"min_len": 6, "max_len": 16, "groups": [], "separator": "-", "regex": ""}, "steps": [{"type": "click_point",
"params": {"point": {"dx": 540, "dy": 250, "rx": 0.4223, "ry": 0.3479, "ref_w": 1280, "ref_h": 720, "anchor":
"tl", "ref_dpi": 96}, "button": "left", "double": false, "jitter_px": 0, "settle_ms": 30, "hold_ms": 30,
"after_ms": 120}, "enabled": true, "label": "", "id": "a1b2c3d4e5f60718"}], "keywords": {"groups": {...}, "order":
["rate_limited", "used", "expired", "invalid", "ineligible", "success"], "fuzzy": true}, "policy": {...},
"template": null, "created_at": "2026-11-17T15:00:00+08:00", "updated_at": "..."}`.

### 5.3 Step types (G4 executes, G7 edits; defaults in models.py)
| type | Label | Parameters (default) | Behaviour |
|---|---|---|---|
| `focus_window` | 切換到視窗 | restore_minimized (True), timeout_ms 3000, settle_ms 200 | bring the target to front (the runner also does this before every code); failure -> pause FOCUS_LOST |
| `click_point` | 點擊位置 | point (required), button left, double False, jitter_px 0, settle_ms 30, hold_ms 30, after_ms 120 | resolve with `coord_mode` and the window DPI, +-random jitter, guard (point on target), click, wait |
| `click_text` | 點擊文字（OCR） | text ("" - must be set; templates use e.g. "兌換\|Redeem"), match exact, region None (= client), nth 0, offset_x/y 0 (px at 96 DPI, x window_dpi / 96), min_score 0.5, upscale 0 (auto), timeout_ms 3000, poll_ms 500, fallback_point None, on_not_found fail, button/double/settle/hold/after | capture -> OCR -> `find_text` (REGEX: the whole text is one pattern); poll until timeout; auto upscale = retry at 2x when not found and the doubled long side stays <= 4096 px; not found -> click fallback_point, else on_not_found: fail -> StepError 「找不到文字「{text}」」, continue -> log 「沒有出現「{text}」，略過這一步」 and go on (dismiss a popup only if it is there) |
| `type_code` | 輸入序號 | mode unicode, key_delay_ms 15, hold_ms 0, clear_first True, clear_method ctrl_a, split none, separators "-_", group_sizes [] (= code_format.groups), between tab, strip_separators False, verify_region None, after_ms 100 | clear; `codes.normalize.split_code` (NONE: the code exactly as shown in the queue, separators removed only with strip_separators; SEPARATOR: at the separators the code kept from its source, segments may differ in length; FIXED: group sizes); type each segment (VK mode closes the target IME and restores it); Tab between segments when `between` = tab;
with `clear_first` each later box is SELECTED before its segment (Ctrl+A, or End + Shift+Home; nothing for the
backspace method) so an old code left in boxes 2..n is replaced - no deleting key, because Backspace in an empty
auto-advance box jumps back on OTP-style pages (gate G-08); verify: the NFKC, case-folded OCR text of verify_region without spaces and separators must contain the code without separators, else StepError 「輸入內容與序號不符（可能被輸入法改寫或權限阻擋）。請改用「貼上」或關閉注音後再試。」 |
| `type_text` | 輸入文字 | text template `{code} {index} {date} {time}`, mode, key_delay_ms, hold_ms, clear_first False, clear_method, after_ms | e.g. `/redeem {code}` |
| `key` | 按鍵／組合鍵 | keys "Enter" (combo of KEY_NAMES), repeat 1, interval_ms 50, hold_ms 0, after_ms 100 | `win32.input.press_combo` |
| `wait` | 等待 | ms 1000, jitter_pct 0 | uniform(ms*(1-j), ms*(1+j)) through RunControl.sleep |
| `wait_text` | 等待文字出現 | text, match contains, region None, appear True, timeout_ms 5000, poll_ms 500, on_timeout fail, upscale 0 | poll until present (appear) / gone; timeout: fail -> StepError, continue -> warning log |
| `ocr_check` | 辨識結果 | region (REQUIRED - validation ERROR and `missing_setup()` when None), initial_delay_ms 800, timeout_ms 5000, poll_ms 500, save_evidence True, upscale 0, only_new_text True | wait, then poll: capture (own windows masked), OCR, `classify_text(text, profile.keywords)` until not UNKNOWN or timeout; with only_new_text the text is only the lines whose `norm_match` text is NOT in the baseline read taken before the submitting step (2.5) - static page text and the previous code's message are ignored; no new line before the timeout -> UNKNOWN 「送出後結果區沒有變化」; sets the result; message = OCR text (<= 200 chars, 「未讀到任何文字」 when empty); evidence PNG of the last capture when both save flags are on |
| `unknown` | 未知步驟 | kept verbatim | skipped with a warning (from a newer version) |
OCR options in steps: `OcrOptions(upscale=params.upscale or 1, det_side=settings.ocr.det_side)` (960) for EVERY read -
a larger det_side lost small text in sparse scenes (measured, T13); large clients need a region, not a larger
detector input. Text matching is strict by default (exact; ocr.md: substring matching caused wrong clicks).
`RunSession.test_step(..., dry_run=True)` resolves geometry, runs OCR and reports (StepTestResult) without sending
input; dry runs never wait for `wait` steps. A step "possibly submits" when its index is >= `Profile.first_submit_index()`
and it sent input (2.5).

### 5.4 Code formats and extraction (G1)
`CodeFormat` = id, charset (class body, e.g. "A-HJ-NP-Y0-9"), case_sensitive, min_len/max_len (separators not
counted), groups (e.g. [5,5,5]), separator, regex. Presets: see `autopress/codes/presets.py` docstring (generic, hoyoverse,
wuthering_waves, blue_archive, steam, xbox, nintendo, custom). The Codes page uses the active profile's format, or
generic without a profile (user can switch presets for an import); `detect_format` suggests one after a paste.
Normalisation never changes a code silently: NFKC, zero-width removed, dash variants -> "-" ("_" and "~" only for
OCR sources, where they are misread dashes); case is kept unless the format is case-insensitive (generic and the
game presets keep case; steam / xbox / nintendo upper-case); characters OUTSIDE the charset may be repaired via
confusable groups, and repaired characters are flagged for every source; valid characters are never changed.
Separators ("-", "_"): formats with groups re-insert `separator` between the groups; formats WITHOUT groups keep the
source separators as written (so `split = separator` can split them and the code is typed as shown); `code_key`
ignores them. `flagged` (low OCR confidence below `Settings.ocr.review_threshold` 0.95, or repaired) puts an item
in REVIEW until confirmed (「已核對」 in the OCR review dialog, 「確認無誤」 in the table) or edited. Look-alikes (0/O/D/Q,
1/I/l/|, 2/Z, 5/S, 6/G, 8/B, U/V, V/Y when both readings are allowed) are only highlighted (`lookalikes`): nearly
every code contains one (96.8-100 % of random 10- and 16-character codes, measured by the product critique), so
they cannot block a run. Constrained re-read: OCR requests for code
images pass `OcrOptions(code_charset=fmt.allowed_chars() + fmt.separator)`.

### 5.5 Result keywords (G4 classifies, G7 edits)
`KeywordConfig.groups[ResultClass] -> list[str]`, `order` (default rate_limited, used, expired, invalid, ineligible,
success), `fuzzy` (True). Defaults = `models.DEFAULT_KEYWORDS` merged over zh-TW, zh-CN, en, ja (proposals,
UNVERIFIED on real games; Korean dropped - the OCR model cannot read Hangul). The rule is implemented ONCE in
`KeywordConfig.classify(text)` (A1; `runner.classify.classify_text` delegates) and tested on the bench_u3 messages,
the HoYoverse API strings and the critique sentences (tests/test_models.py):
1. squash both sides (NFKC, casefold, no spaces/punctuation); empty text -> UNKNOWN;
2. a keyword hits when contained in the text; with fuzzy, 1 edit is tolerated only for non-CJK keywords of
   `FUZZY_MIN_LEN` (9)+ characters ("expired" ≠ "expires", "not found" ≠ "not bound");
3. a SUCCESS hit together with a hit of another class, or with a `NEGATION_MARKERS` entry (無法, 失敗, 未能, cannot,
   unable, ...), is ambiguous -> UNKNOWN (the user is asked);
4. otherwise the first class in `order` with a hit wins.
Ambiguous words are not default keywords: no bare "redeemed" / "claimed" (failure messages say "cannot be
redeemed"; SUCCESS uses "successfully", "code redeemed", "code claimed"), no bare 過期 / 有効期限 (success messages
say when rewards expire). Keywords must not overlap
(`KeywordConfig.overlaps()` -> warning). Result -> status: `models.status_for_result`.

### 5.7 Codes and statuses
`CodeItem` = id, code, raw, game_key, game, source, source_detail, confidence, char_confs, flagged, lookalikes,
status, message, checked, attempts, added_at, updated_at. Every item belongs to the game of the profile that was
active at import (`game_key` = `Profile.game_key()`, "" = 未指定遊戲 when no profile was active).
| Status | zh-TW / en | Tone, glyph | Meaning | Runnable |
|---|---|---|---|---|
| pending | 待兌換 / Pending | neutral ring | not tried, or interrupted before submit | yes |
| review | 需確認 / Needs review | warning dot | low-confidence or repaired characters, unknown / ambiguous result, interrupted or failed after submit | no (確認無誤 / 重設為待兌換) |
| running | 兌換中 / Running | accent dot | current code | - |
| success | 成功 / Redeemed | success dot | result matched success | no (重設為待兌換) |
| submitted | 已送出（未確認） / Submitted (unconfirmed) | success ring | submitted, no result check in the profile; not skipped by history by default | no (重設為待兌換) |
| used | 已使用 / Already used | violet dot | | no (重設為待兌換) |
| invalid | 無效 / Invalid | error dot | | no (重設為待兌換) |
| expired | 已過期 / Expired | orange dot | | no (重設為待兌換) |
| cooldown | 冷卻中 / Rate-limited | info dot | rate-limited, retried after the cool-down | yes |
| failed | 失敗 / Failed | error ring | step error before submitting, ineligible (region / level / cap) | via 重試失敗 |
| skipped | 已略過 / Skipped | neutral dash | user chose to skip, or history says already redeemed | no (取消略過) |
Transitions: import -> PENDING (REVIEW when `flagged`; duplicates - same code AND same game - and history-done codes
are not added and are counted in the import summary); editing a code clears flags (REVIEW -> PENDING); row menu /
bulk 略過 / 取消略過 (SKIPPED <-> PENDING); 確認無誤 (REVIEW -> PENDING) and 重設為待兌換 (any final status -> PENDING,
e.g. a batch judged INVALID because of a typing problem) are both `queue.reset(ids)`; 指定給「{game}」 =
`queue.assign_game(ids, key, name)` (unassigned codes, or a renamed game); bulk 標記為已兌換 (SUCCESS, message
「手動標記」 / "Marked manually", plus a history record with run_id "manual" so later imports skip it); Codes
filters: 全部 / 待兌換 / 需確認 / 已完成 / 失敗 / 已略過 (`codes_model.FILTERS`) plus the game filter (active game +
unassigned by default, 「所有遊戲」); runs take only the profile's game (`queue.runnable(selection, game_key)`);
`build_plan` marks runnable items whose code the history already shows as done (`Settings.history_skip_statuses`,
the item's game) as SKIPPED 「紀錄顯示已兌換過」 / "History shows it was redeemed" when `skip_history_on_import`;
run: -> RUNNING -> final (2.5); 重試失敗 = `retry_failed()` (FAILED only; REVIEW may already be redeemed and needs
the user's decision); startup = `recover_after_crash()`. While a run is active (also paused) the items of its plan
are read-only in the Codes page. Messages AutoPress persists are written with both languages available (tr at
write time; a later language switch does not translate old messages).

### 5.8 History
`AttemptRecord` (one JSON line): id, run_id, code_id, code, game, game_key, profile_id, profile_name, status, result,
message, matched_keyword, started_at, finished_at, duration_ms, evidence_path (relative to the data folder). Key =
(game_key, code_key(code)). Written by RunSession for every attempt that reached a final status (also REVIEW and
COOLDOWN); interrupted-before-submit attempts are not written. `HistoryStore.update(record_id, **changes)` edits a
record in place (same id and position) - used when the user resolves an unknown result. Evidence older than
evidence_keep_days is pruned at startup.

### 5.9 Compatibility
Loading never raises for bad content: unknown keys ignored, missing/invalid values -> defaults, numbers clamped,
unknown enum values -> default, unknown step types kept verbatim and skipped. A recorded point / region with a
missing or unusable coordinate loads as None (position not set -> preflight blocks), never as (0, 0); positional
lists (`groups`, `group_sizes`, `minibar_pos`, `quad`, `char_confs`) are rejected whole when one element is bad.
Newer `schema_version` -> loaded best-effort, version kept in memory, UI shows 「此設定檔來自較新版本，部分內容可能
被略過」 and warns before saving; saving always writes the CURRENT version (the dropped fields are gone, so the file
must not claim the newer version). Upgrades: `models.register_migration(kind, from_version, fn)`; `migrate()` runs
them in order. New CodeItem / Profile / Settings fields of v2 have defaults, so v1 files load unchanged.

## 8. Tests

### 8.1 Rules
* Command (project root): `.venv/Scripts/python.exe -m pytest -q`; your group only: `... -m pytest -q tests/test_codes_*.py`.
  Quick loop: `-m "not slow"`. pytest.ini: `testpaths = tests`, `qt_api = pyqt6`, no cache provider.
* conftest (A1): offscreen Qt platform, isolated `AUTOPRESS_HOME` per test, zh-TW, UI fallbacks, fixtures
  `isolated_home`, `clean_env` (child-process env without QT_QPA_PLATFORM), `python_exe`, `text_image` (renders text
  with Windows fonts to BGR), `sample_profile` (every step type, fully set up), `make_items`, `demo_ctx`
  (AppContext from fakes); pytest-qt's `qapp` / `qtbot`.
* Markers: `realinput` - injects real input; skipped unless `AUTOPRESS_REALINPUT=1`; a lock file serializes agents;
  send input only to your own test windows with the foreground guard on; restore clipboard, CapsLock and cursor.
  Tests that merely SHOW real windows on the desktop (child processes on the windows platform) are marked
  `realinput` too. Run: `AUTOPRESS_REALINPUT=1 .venv/Scripts/python.exe -m pytest -q -m realinput tests/<yours>`.
  `slow` - > 2 s.
* GUI tests: pytest-qt on offscreen. Do not judge layout, fonts or colours on offscreen (no real fonts): use
  `tools/snap_widget.py` (windows platform + WA_DontShowOnScreen) and look at the PNG; check 100/125/150 % and both
  themes. Chinese typing in tests: send `QInputMethodEvent` (QTest.keyClicks with CJK crashes Python). Shortcut
  tests send keys to `QApplication.focusWidget()`. Read the maintainer's local PyQt/Windows notes (not in the repo) first.
* A test that needs ANOTHER group's real implementation calls `tests.fakes.skip_if_stub("autopress.codes.queue")`
  first, so it skips (not fails) while that module is a stub; at integration nothing is skipped any more.
* Offscreen Qt windows have no real HWND (`winId()` is not a window): tests that need one create a hidden native
  window with ctypes (CreateWindowExW without WS_VISIBLE, or an HWND_MESSAGE window for hotkeys) or use a
  `clean_env` child process; `GlobalHotkeys.attach` on an invalid handle must not raise.
* Test fixtures and samples must contain the values that trigger the rule under test (lower-case letters for case
  rules, separators for split rules, a second monitor left of the primary for the failsafe, an identical previous
  message for stale-read rules).
* Never write outside `tmp_path` / `isolated_home`; never touch the real %APPDATA%; never run scripts that overwrite
  project files to "see what happens".

## 9. Coding conventions
* Python 3.12, `from __future__ import annotations`, type hints everywhere, dataclasses for data, StrEnum for enums
  (shared ones live in models.py), f-strings, no wildcard imports, absolute `autopress.` or relative package imports.
* Logging: `log = logging.getLogger(__name__)`; no `print` in library code; codes in logs via `logsetup.mask_code`.
* ctypes: `WinDLL(name, use_last_error=True)`, explicit `argtypes` and `restype` for every foreign function,
  `ULONG_PTR = c_size_t`, keep callback references, check return values, `ctypes.get_last_error()` for errors.
* Images: never pass file paths to OpenCV; Pillow for files; Chinese paths must work. Paths in Python source use
  forward slashes. Files: UTF-8 (JSON via storage helpers, CSV with BOM for Excel), atomic writes through
  `storage.write_bytes_atomic` / `write_text_atomic` (never `tempfile.mkstemp`).
* Dialogs always get a parent (main window, or the MiniBar during runs); the app never relies on
  quit-on-last-window-closed.
* No network access at runtime (OCR models load from explicit paths; no update checks); no admin rights required
  (asInvoker); no global hooks; no background processes after exit.
* Qt: create widgets on the GUI thread only; long work off the GUI thread; never block the event loop > 50 ms;
  `QApplication` before any capture; apply pyqt-windows.md (QComboBox popup, spin boxes, hide() focus, tnum fonts,
  QPainter pen reset, maxLength surrogates -> textutil.clean_text).
* Safety invariants of 2.7 are part of the code review for G3 and G4.
* Keep modules focused (< ~600 lines; split into private helpers under your globs).

## 11. Unverified decisions and known risks
1. Default result keywords and game delays are proposals; no real game, exclusive-fullscreen window or anti-cheat
   was tested (research open issues). The attention panel and editable keywords mitigate.
2. Hotkeys are bound to the main window HWND, which is HIDDEN during runs; delivery to a hidden window was not
   measured (expected to work: WM_HOTKEY is posted to the window's thread). G3 must test it; if it fails, bind to a
   never-shown native helper widget instead (same API).
3. Windows-level 125/150 % scaling and mixed DPI were emulated with Qt variables only; the per-monitor-v2 design
   is verified, real high-DPI machines are not.
4. Elevated targets: detection verified on one same-user elevated process; a UAC-elevated game and
   `restart_as_admin` were not tested.
5. OCR accuracy numbers come from synthetic images; O/0 and I/l confusion is font-dependent - hence mandatory review
   highlighting.
6. `MiniBar` never activating relies on WindowDoesNotAcceptFocus -> WS_EX_NOACTIVATE (measured exstyle for that flag
   set); clicking it while a game is foreground was not tested.
7. History in JSON lines, read fully at startup: fine for thousands of records (not measured beyond that).
8. The onedir size: measured 256.6 MB unpacked / 111.4 MB zip at integration; onefile was rejected for start time.
9. Physical-input detection compares GetLastInputInfo with our last SendInput; it never fired with real input in the
   research (only its premise was measured).
10. `SetWindowDisplayAffinity(WDA_EXCLUDEFROMCAPTURE)` with mss / BitBlt is UNVERIFIED: the A2 probe on 2026-11-17
    could not measure it (the session was locked: foreground `Windows.UI.Core.CoreWindow`, captures black). The
    design does not depend on it - masking own window rects is deterministic; G3 measures and reports.
11. Typing modes were verified only against Qt widgets (win32_input.md 1): browsers with the Bopomofo IME and game
    engines that read raw input are unmeasured (unicode VK_PACKET input is invisible to raw input, 0/50). The
    in-game template uses VK mode with IME closing and a 30 ms hold, the wizard's 測試一筆 plus `verify_region` and
    the invalid-streak pause catch a mode that types nothing or the wrong text.
12. The keyword rule v2 (no bare redeemed / claimed / 過期, fuzzy only from 9 characters, SUCCESS + other class or
    negation -> UNKNOWN) and the only_new_text baseline were checked on text samples only, not on real pages; pages
    that re-render an identical message in place give UNKNOWN 「送出後結果區沒有出現新的訊息（可能和上一筆的訊息
    相同）」 - two valid codes in a row on a page whose result label keeps 「兌換成功」 pause at the second code, and a
    repeated rate-limit message after a cool-down is UNKNOWN too. Integration decision: kept as the safe default (a
    stale message read as the new result would mark a code redeemed forever); the user's choice in the attention
    now feeds the failure counter (G-11), so confirming each such code no longer stops the run; turning
    only_new_text off is only safe when the page clears the label at submit. Dialog / toast results are unaffected.
13. DPI-scaled offsets assume web pages and dialogs scale linearly with Windows scaling; not measured on a real
    125 % / 150 % machine (11.3). Template coordinate modes (web: offset, game: auto) are proposals.
14. Timing constants chosen without measurement: 1.5 s F8-after-auto-pause window, 0.7 s mini bar button lock,
    2 s resume countdown, 5 s client-rect settle after restoring a minimized target, OCR max_side_len 4096.
15. `SetThreadExecutionState` keep-awake and the `restart_as_admin` + `--wait-lock` hand-over are standard API use,
    not measured here.
