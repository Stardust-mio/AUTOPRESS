# 使用者需求（原話整理，2026-11-17）

本檔記錄使用者在對話中直接提出的需求，是 SPEC.md 必須涵蓋的最低範圍。後續若 SPEC 與本檔衝突，以本檔為準並回頭修 SPEC。

## 原始需求

1. 用 PyQt6 做介面，要**現代化的介面**。
2. 用途：**自動輸入遊戲序號**（兌換碼）——遊戲序號常常要輸入一大堆。
3. 最好有 **OCR 輔助**：辨識序號，以及輔助「輸入、送出」那些動作。
4. **通用型**，要給所有人用（不限定某一款遊戲）。
5. 使用者說明：此工具不影響遊戲本身（只是代替手動輸入序號）。
6. 要能**多個序號依次輸入**（一批序號自動一個接一個輸入、送出，直到全部做完）。
7. 放到 **GitHub**：開發期間是私人（private）repo `Stardust-mio/AUTOPRESS`（之後可改名）。**發佈方式（2026-11-17 使用者選 A）：完成後把 repo 改成公開，用 GitHub Releases 提供 exe 壓縮檔下載**（原始碼公開也滿足 PyQt6 的 GPL 要求）。改公開前必須：對整個 git 歷史做隱私掃描、告知 commit 會顯示的作者名稱與 email，並在改公開的當下再請使用者確認一次。**使用者明說「發布」之前，不改公開、不建立 Release**（2026-11-17 使用者交代）。
8. 使用說明要用 **「截圖＋說明」** 的方式呈現（每個畫面截圖、標出各區塊並逐條解釋），並且**放到 GitHub 上**（README／docs，GitHub 可直接顯示）。正式版截圖必須來自實際程式畫面，不能用設計稿充當。
9. 真實輸入測試（realinput）由 Claude 自己跑，使用者不必在場；但電腦鎖定時不能跑，要等解鎖後再跑（2026-11-17 使用者授權）。

## 「多個序號依次輸入」的驗收要點（主對話展開，供 SPEC 對照）

- 序號清單＝佇列：依清單順序逐一執行同一套流程（點輸入框→清空→輸入→送出→等待→（可選）OCR 判讀結果→關閉彈窗），全部做完自動停止。
- 可調整順序、只跑勾選的／只跑尚未完成的；每筆序號有狀態（待處理、執行中、成功、已使用、無效、過期、失敗、略過）。
- 每筆之間的間隔可設定（固定秒數＋隨機抖動）；可暫停／繼續（從下一筆接著做）、停止；中途關閉程式後再開，可從未完成的那筆繼續。
- 已成功或已使用過的序號自動略過（歷史紀錄）；失敗的可一鍵重試。
- 偵測到「操作過於頻繁」之類訊息時：停止，或冷卻一段時間後自動繼續（可設定）；連續失敗 N 筆自動停止。
- 支援「一個序號要拆成多格輸入」的兌換頁（例如 XXXXX-XXXXX-XXXXX 分三格）：可依分隔符或固定字數拆段，段與段之間送 Tab 或不送（有些輸入格會自動跳格）。
- 執行中顯示進度（第幾筆／共幾筆、預估剩餘時間）與即時紀錄，可匯出結果。
